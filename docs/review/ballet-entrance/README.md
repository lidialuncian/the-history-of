Status: **prototype for visual review, not the completed entrance animation**. Lives only at `/ballet/entrance-preview`; the real homepage and direct Ballet route are unchanged. No production rollout or production PR yet.

PR #2 merged before implementation. Fetched `origin/main` at `c709524` and merged it into `feat/ballet-entrance-animation` (merge commit `1c70954`). Main is an ancestor of this branch; the proof does not duplicate the Ballet Phase 1 changes.

## Review the motion

1. Run `npm run dev` and open [the isolated preview](http://localhost:3000/ballet/entrance-preview).
2. Scroll to the real homepage collection rendered inside the study. Select the Ballet exhibit by pointer, touch or keyboard.
3. The source artwork switches to a clean stage plate while a transparent figure emerges, changes preparation/turn/resolve poses once, then travels into a measured copy of the real Ballet hero. A native handoff opens `/ballet#ballet-story` and focuses its main landmark.
4. Skip is visible immediately; Escape also ends the study. Use Back to return and intentionally play again. Direct Ballet visits never replay it.
5. With reduced motion or data saving enabled, or missing optional assets, the original Ballet link navigates directly.

The nine key poses are deliberately stepped. This recording demonstrates layered emergence, anatomical pose changes through one turn, and measured travel into the hero. It does **not** establish graceful production choreography, exact identity continuity or a seamless final silhouette match.

## Audit of available art

| Asset | Dimensions | Encoded size | What it provides |
| --- | --- | --- | --- |
| `public/images/exhibits/ballet.webp` | 1672 × 941 | 91,768 bytes | Flattened landscape card illustration. No alpha, separable figure or motion. |
| `public/images/exhibits/ballet-arch-v2.webp` | 1122 × 1402 | 120,996 bytes | Flattened portrait hero variant. Extra overhead space, different figure scale/placement and some generative pose/detail differences. No alpha or motion. |

Neither flattened image can supply a convincing three-dimensional turn through CSS rotation. Both were inspected visually and with Sharp metadata. Their different crops and poses require explicit matching at both ends of any production transition.

## Two feasible approaches

| Approach | Advantages | Costs / remaining risks |
| --- | --- | --- |
| Transparent full-body frame sequence plus matched clean plates — this proof | Figure moves independently of its setting; explicit single-turn poses; no new runtime library; simple static fallback. | Needs professionally aligned intermediate frames, stable identity/foot pivot and precise first/last pose matching. More decoded image memory. Nine generated key poses are insufficient for smooth motion. |
| Authored short motion clip with a tested alpha or mask strategy | A choreographer/animator can deliver continuous fabric, weight transfer and spotting. | Requires new original/licensed footage or rendered animation, browser-specific playback/alpha validation, precise compositing and load/failure handling. No video-generation tool or motion clip was available in this checkout. |

CSS and requestAnimationFrame author **translation, size and compositing only**. The dancer's actual movement comes from different raster poses showing preparation, front, profile, back and return. There is no CSS rotation, mirrored-image turn, generic page fade or repeated spin.

## Prototype assets and attribution

- `public/images/ballet-entrance/turn-study.webp`: 1254 × 1254, true alpha, 3 × 3 sheet; nine AI-generated full-body poses based on the existing card illustration.
- `public/images/ballet-entrance/stage-plate.webp`: 1672 × 941 clean stage plate generated by removing the illustrated dancer from the existing card art.
- Both created with the built-in imagegen tool, then encoded to WebP using the installed Sharp package. Original source art is preserved. Exact [asset prompts](asset-prompts.md) are tracked.
- The study control bar visibly labels the nine AI poses as provisional. These are illustrative animation assets, not archival footage, a real dancer's performance or historical evidence.

The current sheet has approximate rather than locked scale, pivot, identity and cloth continuity. The source-to-cutout replacement is visible. The destination temporarily reuses the landscape plate inside the arch, so its background/crop and final silhouette differ from the real hero. The final brief handoff blend resolves to the unchanged hero; it is not the dancer motion. These seams are explicit review findings, not accepted production compromises.

## Additional assets required before production

1. A matching source cutout and a separate clean card plate, aligned to the exact source image, including all fingertips/feet.
2. An approved single-turn choreography: a clear preparation/step out, one pirouette with stable supporting foot and spotting, then a controlled landing. As an initial asset target, about 48–72 genuinely distinct, registered frames at 24fps; review timing before final export.
3. Fixed cell dimensions, consistent foot pivot, scale, costume, face and soft alpha edges across all frames; safe padding for moving limbs at phone and desktop sizes. Nine key poses alone are not final animation.
4. A matching hero background plate and a final dancer pose that aligns pixel-accurately with the approved portrait hero, avoiding double dancers and crop jumps.
5. Optimized delivery and a verified mobile budget after the visual approach is approved. A matched short clip is an alternative to the frame sequence, not an asset currently provided.

## Implementation and cost

- New route files only: `src/app/ballet/entrance-preview/page.tsx`, `EntranceStudy.tsx`, `preview.css`.
- Reuses the real homepage and Ballet server components inside the isolated study. No edits to their source or to existing card semantics/layout.
- Native link interception happens in capture phase only for unmodified primary activation of Ballet in this preview. Ctrl/Cmd/Shift/Alt clicks, download/new-tab targets, other subjects and fallback navigation retain normal behavior.
- Optional assets preload/decode only on the study route. If not ready, the link works immediately. No delayed loading gate.
- Total optional image transfer is approximately 520KiB. Decoded image pixel storage is approximately 12MiB before renderer overhead. No added dependencies; existing Motion is not needed for this measured-frame spike.
- Production study controller chunk measured 6,989 bytes (2,814 bytes gzip), stylesheet 1,733 bytes (682 bytes gzip), excluding shared framework code. Tiny final comment/noscript edits may change these figures slightly. No animation runtime/assets added to the normal homepage entry.
- 3.8-second bounded sequence; one requestAnimationFrame loop, cancelled on unmount, Skip, Escape, resize, backgrounding or a changed reduced-motion preference. Independent 4.6-second completion guard. Decoration never captures pointer input or traps focus.
- One desktop recording observed 150 callback intervals averaging 16.9ms, maximum 33.4ms. This includes recording overhead and is **not** a low-end mobile performance certification. The sprite itself remains nine stepped poses regardless of callback rate.
- For this isolated proof, a deliberately documented native document handoff preserves browser hash focus. Stage B should evaluate shared overlay persistence and focus management across client navigation after visual review.

- Visible Skip activated with keyboard and Escape interruptions navigate to Ballet and focus the story.
